# World Clean Biz 文章分享与推荐区改版设计

日期：2026-08-14

## 目标

改进所有 Blog 文章页的页尾阅读动线：

1. 提供读者可直接使用的社交分享入口。
2. 将推荐文章区改成更紧凑、专业的编辑精选样式。
3. 推荐内容固定为 3 篇深度分析，并优先展示连载内容。
4. 保持文章正文、业务咨询 CTA 和其他站点页面不变。

## 当前问题

- 文章页没有社交分享组件。
- 当前 `Related Articles` 使用单列大图长卡片，重复展示较长摘要，使页尾过长。
- 当前推荐逻辑在同分类文章不足时从全站文章补满，可能混入相关性较弱或搜索型内容。
- 推荐区、作者信息、连载导航和业务咨询 CTA 都处于文章末尾，但视觉层级不够清晰。

## 已确认的设计方向

### 分享入口

桌面端在正文左侧显示轻量悬浮分享栏。分享栏随正文阅读区域保持可见，但不覆盖正文。渠道包括：

- LinkedIn
- X
- Facebook
- WhatsApp
- 复制链接

平板和手机端不显示悬浮栏，避免遮挡正文。正文结束后显示：

- 系统分享按钮；仅在浏览器支持 Web Share API 时出现。
- LinkedIn、X、Facebook、WhatsApp 和复制链接的直接入口。

复制成功后显示短暂的 `Link copied` 状态。所有图标按钮必须具有可见的焦点状态、明确的 `aria-label` 和可读的提示文字。

### 推荐文章区

推荐区采用已确认的“编辑精选网格”方案：

- 标题使用 `Continue Reading`。
- 增加一句简短说明，表达这些内容是同一行业中的延伸分析。
- 桌面端使用宽于正文阅读栏的三列网格。
- 每张卡片显示封面、分类或连载标记、标题、阅读时长和阅读提示。
- 不显示文章摘要，减少重复信息和页面长度。
- 手机端改为带缩略图的紧凑列表，而不是连续三张大图卡片。
- 推荐区之后保留现有业务咨询 CTA，并用间距或背景区分两个层级。

## 推荐内容规则

### 推荐池

推荐池只允许 `contentClass === "editorial"` 的公开文章。所有 `contentClass === "search"` 的 Buyer Guide、Sourcing Guide、品牌归属、产品比较、解释及故障类内容均不进入推荐池。

每个文章页固定展示 3 篇推荐文章。推荐结果采用“稳定随机”：

- 同一篇文章在相同内容版本下始终得到相同组合。
- 不同文章通过当前文章 slug 作为种子得到不同组合。
- 候选文章集合变化后允许组合更新；候选集合不变时，单纯重新构建不会改变结果。
- 不在浏览器中每次刷新重新随机，避免布局跳变和不可重复测试。

### 连载优先

- 非连载文章优先保留一个位置给连载深度分析；存在多个候选时使用稳定随机选择。
- 同一连载只提供其最新的合格文章作为候选，避免推荐网格被同一连载占满。
- 当前文章属于连载时，该页面已有 `All Episodes` 导航；推荐区排除当前连载的其他文章，避免重复。
- 连载推荐卡显示连载名称，普通文章显示分类。

### 稳定选择流程

1. 读取所有公开文章并筛选 `editorial`。
2. 排除当前文章。
3. 如果当前文章属于连载，排除同一连载的其他文章。
4. 将每个其他连载折叠为最新一篇合格文章。
5. 使用当前文章 slug 与候选文章 slug 生成稳定排序值。
6. 非连载文章先选择一篇连载候选，再从尚未使用的全部合格候选中选满 3 篇。
7. 返回 3 篇互不重复的文章。

测试必须确保当前内容库中的每篇公开文章都能得到 3 篇推荐。如果未来深度分析库存不足，构建验证应明确报错，而不是静默插入搜索型文章或占位内容。

## 页面结构

文章正文与页尾内容按以下顺序呈现：

1. 文章正文
2. 移动端分享区；桌面端使用正文侧边悬浮栏
3. 标签和作者信息
4. 连载导航；仅连载文章显示
5. `Continue Reading` 推荐区
6. 现有业务咨询 CTA

正文继续保持现有 780px 阅读宽度。推荐区在桌面端使用独立的宽容器，以容纳三列卡片；移动端恢复为单列紧凑列表。

## 组件与职责

### `ArticleShareActions`

客户端组件，职责限定为：

- 根据文章标题和规范 URL 生成分享行为。
- 打开各社交平台分享入口。
- 在支持时调用系统分享。
- 复制文章链接并显示成功或失败反馈。
- 提供桌面悬浮与移动端内嵌两种响应式呈现。

组件不读取文章文件，也不负责推荐逻辑。

### `getRelatedEditorialInsights`

纯数据函数，接收当前文章与完整文章列表，返回 3 篇稳定选择的深度分析文章。其职责包括：

- 内容类型过滤。
- 当前文章与同连载排除。
- 连载候选折叠和优先。
- 稳定排序与去重。

函数不负责 JSX、图片属性或客户端状态，便于独立测试。

### 推荐区视图

文章模板负责调用推荐函数并渲染推荐区。卡片继续使用现有响应式图片工具，避免新建独立图片路径或绕开文章图片管线。

## 失败与兼容处理

- Web Share API 不可用：隐藏系统分享按钮，直接渠道仍可用。
- Clipboard API 不可用或失败：使用兼容复制方式；仍失败时显示明确反馈，不显示虚假的成功状态。
- 分享弹窗被阻止：保留可打开的标准链接，不中断当前文章。
- 推荐文章缺少封面：沿用文章页当前的安全备用图机制。
- 推荐文章不足 3 篇：构建测试失败并指出文章 slug，不用无关内容或占位卡片补足。
- 外部分享链接使用新窗口时添加安全的 `noopener` 和 `noreferrer` 行为。

## 响应式与无障碍要求

- 桌面悬浮栏只在正文两侧有足够空间时显示。
- 平板和手机端不得出现固定元素遮挡正文、表格或图片。
- 所有交互目标满足至少 44px 的触控尺寸。
- 图标不能作为唯一的无障碍名称。
- 键盘用户能够依次访问全部分享入口，并清楚看到焦点。
- `prefers-reduced-motion` 下不加入非必要动画。

## 验证方案

### 推荐逻辑测试

- 每页返回恰好 3 篇文章。
- 推荐全部为 `editorial`。
- 不包含当前文章。
- 结果没有重复。
- 同一输入多次运行结果一致。
- 不同当前文章能够产生分散的组合。
- 非连载页面优先出现连载候选。
- 连载页面不重复推荐同系列文章。

### 分享交互测试

- 各渠道接收规范文章 URL 和文章标题。
- 支持 Web Share API 时显示并调用系统分享。
- 不支持时仍可使用直接渠道。
- 复制成功、失败及重复操作都有正确反馈。

### 页面与构建验证

- 运行文章页相关测试。
- 运行完整 `npm run build`。
- 桌面端检查悬浮分享栏、三列推荐网格及 CTA 顺序。
- 390px 手机宽度检查内嵌分享区、紧凑推荐列表及无横向溢出。
- 验证推荐图片无断链，并继续使用现有响应式图片属性。

## 改动范围

允许修改：

- Blog 文章模板。
- 新增文章分享组件。
- 文章推荐选择函数。
- Blog 文章相关样式。
- 对应的测试文件。

不修改：

- 文章正文和 frontmatter。
- 首页、导航、Footer 或其他页面。
- 文章图片资产和图片准备流程。
- 业务咨询 CTA 的文案和行为。
- 发布或部署配置。

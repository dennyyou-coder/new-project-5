# WCB 文章图片自动优化与发布门槛设计

日期：2026-08-09
状态：已完成讨论，待用户审核书面规范

## 1. 目标

为 World Clean Biz 建立统一的文章图片入口。无论图片由 Codex 生成、由 Denny 提供，还是来自 `WorldCleanBizAssets`，进入网站前都必须完成尺寸调整、格式优化、桌面与手机适配、尺寸登记和预算验证。

系统需要同时解决两个问题：

1. 继续降低现有文章完整浏览时的图片下载量。
2. 阻止新文章再次把未经优化的大图带入生产网站。

图片超出单张或单篇预算时，发布必须失败。构建和部署阶段只验证，不临时修改图片。

## 2. 范围

本设计包括：

- AI 生成的文章封面和正文视觉图；
- Denny 提供的手机照片、相机照片、产品照片和现场照片；
- `/Users/youdenny/Desktop/WorldCleanBizAssets/{slug}/` 中的文章素材；
- 现有文章使用的本地图片；
- 图片格式、尺寸、质量、响应式版本、清单和发布预算；
- 文章 HTML 中的 `width`、`height`、`srcset`、`sizes`、懒加载和首屏优先级；
- 本地测试、GitHub 检查和 Vercel 构建门槛。

本设计不包括：

- 改写文章正文、标题、slug、CTA、FAQ 或 Schema 内容；
- 改变现有图片的叙事顺序；
- 将原始素材库迁入 Git 仓库；
- 引入付费图片 CDN；
- 把所有图片改造成 Next.js `Image` 组件；
- 为了压缩体积而接受明显模糊、文字不可读或人物主体被错误裁切。

## 3. 核心原则

1. **单一入口**：文章图片不能绕过处理器直接进入正式网站。
2. **原图与发布图分离**：原图保留在素材库，网站仓库只保存发布版本。
3. **准备与验证分离**：准备命令可以写入优化图片；构建和验证命令只读。
4. **移动端优先节省**：手机不应下载与桌面相同的大图。
5. **保持现有 URL**：历史文章不批量搬迁图片目录，避免不必要的 Google 图片索引变化。
6. **画质优先于机械过关**：自动压缩达到最低可接受画质后仍超标，应停止发布并报告，不继续破坏图片。
7. **预算按实际下载计算**：桌面与手机预算分别计算浏览器实际选择的资源，不把所有存储变体简单相加。

## 4. 素材来源与处理规则

### 4.1 Codex 生成图片

- 封面在生成阶段使用 16:9 构图，目标画布为 1600×900。
- 正文图根据内容使用 16:9、4:3 或必要的数据图比例，最长边不超过 1600px。
- 生成工具的原始输出先保存到 `/Users/youdenny/Desktop/WorldCleanBizAssets/{slug}/`。
- 原始大 PNG 不直接复制到 `public/`。
- 即使生成时已选择正确尺寸，仍必须经过统一处理器，因为生成工具不能精确保证最终文件体积。

### 4.2 Denny 提供的照片

- 读取 EXIF 方向并自动旋转到正确方向。
- 删除不需要进入网站的相机元数据。
- 统一转换为 sRGB，避免不同设备出现明显色差。
- 正文照片保持完整画面，只进行旋转、缩放和压缩。
- 照片用作封面时，生成 16:9 发布版本；原始照片不修改。
- 如果自动封面裁切会损坏人物、产品或文字主体，处理器必须停止并要求人工确认，不得强行裁切。
- 模糊、严重欠曝、过曝或分辨率不足的照片应报告质量警告；不能用重复放大伪装成合格图片。

### 4.3 现有文章图片

- 保留现有公开路径和文章引用。
- 在原目录生成必要的优化版本及手机版本。
- 被新发布版本取代的 PNG/JPG 只有在引用已更新、输出存在且可从 Git 恢复时才能从网站仓库删除。
- 不修改 `/Users/youdenny/Desktop/WorldCleanBizAssets` 中的源文件。
- 历史文章如果没有对应素材文件夹，只允许对网站仓库中的现有发布图做同路径、同格式的机械压缩和响应式变体生成；不得重新裁图、替换画面或推测原始素材。

## 5. 输出目录与命名

新文章继续遵循现有视觉系统：

```text
/Users/youdenny/Desktop/WorldCleanBizAssets/{slug}/
  01-cover.png
  02-*.png
  03-*.jpg
```

网站发布目录：

```text
public/images/articles/{slug}/
  01-cover.webp
  01-cover-800.webp      # 仅在能显著减少手机流量时生成
  02-*.webp
  02-*-800.webp          # 仅在能显著减少手机流量时生成
```

规则：

- `01-cover.webp` 同时作为文章封面、目录缩略图和默认社交图片。
- MDX 只引用主路径，例如 `/images/articles/{slug}/01-cover.webp`。
- 手机路径由图片清单和渲染器自动补充，不写进文章正文。
- 如果手机版不能至少减少 20 KB 或 25% 下载量，则不生成额外文件，由手机复用主文件。
- 新输出不能静默覆盖内容不同的同名文件。源指纹不同但目标路径相同时必须失败。
- 历史图片的现有主 URL 和扩展名保持不变。JPEG、PNG 和 WebP 分别在原格式内优化；额外的手机变体可以使用 WebP。只有用户另行批准 URL 迁移时才能改变历史主路径。

## 6. 图片预算

### 6.1 单张预算

| 类型 | 桌面版上限 | 手机版上限 |
|---|---:|---:|
| 文章封面 | 300 KB | 120 KB |
| 普通正文图片 | 220 KB | 100 KB |
| 文字或数据较多的图表 | 300 KB | 140 KB |
| Logo、透明图、小图标 | 150 KB | 150 KB 或共用主文件 |

### 6.2 单篇文章预算

普通文章通常为 1 张封面和 4 张正文图：

- 桌面端总量不超过 1.5 MB；
- 手机端总量不超过 750 KB。

图片较多的深度文章：

- 桌面端总量不超过 2.5 MB；
- 手机端总量不超过 1.2 MB。

深度文章不能仅根据图片数量自动获得更高预算。文章需要包含超过 8 张有独立信息价值的正文图，才可使用深度文章预算。预算类型应由处理结果报告明确记录。

### 6.3 首屏预算

- 每篇文章只允许一张首图使用 eager 或高优先级加载。
- 其他正文图、作者图和相关推荐图片全部懒加载。
- 手机和桌面首屏均只计算实际选择的封面资源。

## 7. 自动编码策略

处理器按以下顺序尝试：

1. 自动旋转并转换为 sRGB。
2. 桌面版最长边限制在 1600px；不允许放大。
3. 手机版最长边限制在 800px；必要时可降至 720px；不允许放大。
4. 摄影和 AI 场景图优先使用 WebP，初始质量 84。
5. 超标时依次降低质量和尺寸，但普通照片最低质量不得低于 72。
6. 含细小文字、线条或透明背景的图表优先使用高质量 WebP；如果可读性下降，可以使用优化 PNG。
7. 图表不能通过降低到不可读画质来满足预算。
8. 最低画质或最低尺寸后仍超标，处理失败并报告具体文件、实际体积、上限和建议动作。

处理器需要记录实际使用的格式、宽高、质量、字节数和源文件指纹，确保结果可审计、可重复。

## 8. 图片清单

生成的清单由代码读取，文章作者不手工维护。每张主图片至少记录：

```json
{
  "/images/articles/example/01-cover.webp": {
    "role": "cover",
    "width": 1600,
    "height": 900,
    "bytes": 245000,
    "mobileSrc": "/images/articles/example/01-cover-800.webp",
    "mobileWidth": 800,
    "mobileHeight": 450,
    "mobileBytes": 93000,
    "sourceHash": "sha256:..."
  }
}
```

清单必须确定性生成：同一输入和处理版本应产生相同路径与字段顺序。构建阶段发现清单与文件不一致时必须失败。

## 9. 文章渲染规则

- 主图片路径继续作为 `src`，保证旧浏览器和现有 URL 可用。
- 存在手机版本时输出 `srcset` 和 `sizes`。
- 所有本地文章图片从清单读取真实 `width` 和 `height`。
- 封面使用高优先级加载，不使用 `loading="lazy"`。
- 正文图片使用 `loading="lazy"` 和 `decoding="async"`。
- 图片没有清单记录时，不允许用猜测尺寸继续发布。
- 社交元数据继续引用主封面，不使用手机变体。

## 10. 命令与职责边界

计划提供三个明确入口：

1. `prepare:article-images -- --slug {slug}`
   - 读取对应素材目录；
   - 生成发布图片和清单；
   - 允许写文件；
   - 输出节省体积和预算报告。

2. `prepare:article-images -- --all`
   - 用于历史文章迁移；
   - 只处理可确定归属和用途的图片；
   - 不能推测缺失的素材归属。
   - 历史素材文件夹缺失时，只能优化仓库中的现有发布图并保持主 URL，不得执行重新裁切或视觉替换。

3. `verify:article-images`
   - 只读；
   - 检查格式、尺寸、路径、清单、单张预算、单篇预算、首屏规则和目录增长；
   - 用于本地、GitHub 和 Vercel 构建门槛。

生产构建的 `prebuild` 只运行生成清单的一致性检查和预算验证，不在 CI 中生成或重写图片。

## 11. 仓库与部署体积保护

当前文章相关目录基线为：

- `public/images/articles`：约 25.5 MB；
- `public/images/blog`：约 92.5 MB；
- `public/images/insights`：约 161.1 MB；
- 合计约 279 MB、2,166 个文件。

历史迁移需要同时压缩现有主文件、删除被取代的网站副本，并仅在手机版能产生明确收益时创建变体。

迁移完成后，上述三个目录的合计体积原则上不得超过基线的 110%，即约 307 MB。超过时必须停止并检查重复文件、低收益手机变体或未删除的旧格式，不能以“手机更快”为由无限增加部署包。

单次新增文章也应报告文章目录的净新增字节数和文件数。

## 12. 失败与警告

以下情况必须阻止发布：

- 处理单篇新文章时，`/Users/youdenny/Desktop/WorldCleanBizAssets/{slug}/` 不存在；
- `01-cover` 不存在；
- 文章引用的本地图片不存在；
- 主文件或需要的手机文件缺失；
- 清单尺寸、字节数或源指纹与文件不一致；
- 单张或单篇预算超标；
- 超过最低可接受压缩质量后仍超标；
- 自动封面裁切会破坏主体且没有人工确认；
- 不同源文件试图覆盖同一输出路径；
- 历史迁移使文章图片目录超过仓库体积门槛。

历史批量迁移中缺少素材文件夹本身不阻止同路径机械优化，但必须禁止任何需要原图判断的裁切、放大或视觉替换。

以下情况可以警告但不自动阻止发布，除非视觉审核失败：

- 原始照片分辨率偏低但没有被放大；
- 原图存在轻微噪点、欠曝或压缩痕迹；
- 小图片的手机版本收益不足，因此复用主文件。

错误报告需要使用文章 slug 和图片文件名说明问题，并给出下一步操作，不能只输出技术堆栈。

## 13. 历史迁移策略

1. 建立当前图片路径、字节数、尺寸和每篇文章总量基线。
2. 先对普通照片、图表、透明图和手机照片各选择代表文章进行试运行。
3. 检查图片可读性、人物/产品裁切、桌面和 390px 手机布局。
4. 批量处理所有可确定归属的历史文章图片。
5. 保留历史公开路径，不批量搬迁目录。
6. 按首页、Sourcing、流量文章和图片最多的长文章顺序做重点验证。
7. 输出迁移前后桌面下载量、手机下载量、仓库字节数和超预算页面清单。
8. 只有完整测试、生产构建和 Vercel Preview 通过后才允许合并。

## 14. 测试与发布门槛

### 14.1 单元和资产测试

- EXIF 方向纠正；
- 不放大低分辨率照片；
- 桌面和手机尺寸选择；
- WebP 与 PNG 例外规则；
- 自适应质量阶段；
- 同名冲突；
- 清单确定性；
- 单张与单篇预算；
- 手机变体收益阈值；
- 仓库总量门槛。

### 14.2 集成测试

- 一篇新文章从素材目录到 MDX 渲染的完整流程；
- 封面、正文照片、文字图表和透明图组合；
- 缺图、超预算和清单过期时构建失败；
- HTML 中只有封面优先加载；
- 正文图片包含宽高、懒加载、`srcset` 和 `sizes`；
- OpenGraph 继续使用主封面。

### 14.3 发布验证

- 完整 Node 测试套件；
- 内容分类、SEO、图片路径和资产预算检查；
- `npm run build`；
- 桌面和 390px 手机文章检查；
- 首页、Sourcing、普通文章和图片最多的长文章检查；
- Vercel Preview 构建与代表路由验证；
- 最终差异只能包含图片流水线、图片清单、目标图片、相关测试和规范文档。

## 15. 验收标准

设计实施完成后必须满足：

- 新文章无法绕过图片准备和预算验证直接发布；
- Codex 生成图片从构图阶段遵守用途标准，并在发布前自动转码；
- Denny 提供的照片自动纠正方向、调整尺寸并生成合适发布版本；
- 普通文章桌面不超过 1.5 MB、手机不超过 750 KB；
- 深度文章桌面不超过 2.5 MB、手机不超过 1.2 MB；
- 每篇文章只有一张首屏优先图片；
- 正文图片具有真实宽高、懒加载和响应式资源；
- 历史文章 URL、正文和图片叙事顺序不变；
- 文章图片相关目录不超过约 307 MB，除非用户明确批准新的基线；
- 所有自动测试、生产构建和 Preview 验证通过后才能发布。
